# Decisions

Choices made where SPEC.md was silent or where reality forced a deviation.

## Phase 1

1. **Expo SDK 57** (`expo ~57.0.26`, React Native 0.86.3, React 19.2.3, TypeScript ~6.0). Versions are pinned via the lockfile and the `~` ranges in `package.json`. Phase 1 only installs what it uses (Zustand, Jest); Skia, Reanimated, audio, haptics, storage and navigation are added in the phases that need them.
2. **25 levels in total.** Level 1 is the handcrafted tutorial; levels 2-25 are generated (24 generated). The spec text says both "25 generated plus handcrafted level 1" and "25 levels, level 1 handcrafted"; the second reading is used.
3. **Out-of-range tube indices throw `RangeError`** in `getMoveError` and friends. They indicate a bug, not an illegal move, so they are not a `MoveError`.
4. **Deadlock ignores pointless moves.** `isDeadlocked` is "not solved and no *meaningful* move". A meaningful move is a valid move that is not the whole content of a tube poured into an empty tube (that only relabels a tube). Without this a board with a spare empty tube could never report a deadlock when only such moves remain. `getValidMoves` is unchanged and returns every valid move.
5. **Extra tube is added to every snapshot** (initial, history, current). Undo and restart therefore never remove a tube the player paid for, matching §8.2. The extra tube has id `X1`, capacity 4.
6. **`createSession` / `restartLevel` take `now` as a parameter** (default 0 / previous value) so the engine stays free of `Date.now()`. The store passes `Date.now()`.
7. **Solver heuristic is tighter than the spec's.** The spec suggests "colour boundaries between adjacent layers". The solver uses `h = (number of same-colour runs) - (complete tubes at the goal)`. One pour changes the run count by at most 1, and the goal has one run per complete tube, so it is admissible and consistent, and it dominates the boundary count. Exact solves of 7-colour levels take about 15 ms.
8. **Solver state key** sorts all tubes, because Phase 1 has no fixed-position tubes. Fixed positions for locked/catalyst/frozen/extra tubes arrive with Phase 5. The solver throws on locked, frozen or hidden input rather than giving a wrong answer.
9. **Pruning:** pointless relabel moves, sealed sources, and identical destination tubes are skipped. The "skip immediate reverse" rule is covered by the closed set (a state reached at equal or lower cost is never re-queued).
10. **Budget fallback.** If exact A* exceeds `maxNodes` (1.5M), weighted A* (weight 3, 400k nodes) looks for any solution and the result is flagged `exact: false`. Every shipped level was solved exactly.
11. **Level windows are below the spec's upper bounds.** Across thousands of exactly solved random deals with 2 empty tubes, the optimum tops out near 11 / 14 / 18 / 21 / 25 moves for 3 / 4 / 5 / 6 / 7 colours. Bands such as "20-34" for levels 21-25 cannot be reached by random dealing, so `difficulty.ts` ramps smaller windows per level inside what is reachable (levels 21-25: 20-26). Tune after playtesting. Difficulty grade is assigned by level number (easy 2-8, medium 9-15, hard 16-23, expert 24-25).
12. **Dead-end rate** (200 random playouts over meaningful moves) is recorded in a comment per level but is not used to accept or reject. With 2 empty tubes it is almost always near 0, so it does not discriminate yet.
13. **"Too trivial" check:** a deal with fewer than 3 meaningful initial moves is rejected.
14. **Duplicate detection** uses an exact canonical key: sorted tubes minimised over every colour permutation (`levelCanonicalKey`).
15. **Level data format:** levels are written as compact strings (`'GGRR'`, bottom to top, letters R B Y G V O C M) and expanded by `defineLevel`. Tube ids are `T1..Tn`.
16. **Generated levels are deterministic** from `g1:level-<n>`; the PRNG stream continues across rejected deals. `GENERATOR_VERSION` is `g1`.
17. **Tap flow lives in `game/interaction.ts`** (`resolveTap`) as pure code so it is unit tested; the store and later the Skia UI only execute the returned action.
18. **Phase 1 UI** is a plain level list plus a View-based game screen, with no navigation library, persistence or tutorial overlay (Phase 3). Tutorial steps are not shown yet; level 1 is authored so they will happen naturally.
19. **TypeScript 6 needs explicit `types`** (`jest`, `node`) in `tsconfig.json`.

## Phase 2

20. **Packages** (SDK 57 bundled versions, installed with `--legacy-peer-deps` because `expo install` could not reach its version API): `@shopify/react-native-skia 2.6.2`, `react-native-reanimated 4.5.1`, `react-native-worklets 0.10.1`, `expo-audio ~57.0.5`, `expo-haptics ~57.0.3`, `react-native-safe-area-context ~5.7.0`. Dev only: `react-native-web`, `react-dom` (browser QA), `@react-native/jest-preset` (peer of `jest-expo`).
21. **One Skia canvas for the whole board**, not one per tube. The pouring tube must draw above its neighbours, and a pour needs stream and particles across tubes. Tap targets and screen reader labels are separate `Pressable`s over the canvas (`components/Tube.tsx`). The canvas is 72 dp taller than the board and extends upward so a tilted tube is never clipped; it sits in a `pointerEvents="none"` wrapper.
22. **Animations are driven from engine events plus a committed-state swap.** The engine state updates immediately; `GameBoard` keeps a "shown" state, animates one `Plan` (a shared value) from `poured` events and a clock, then commits. Slot indices in a `Plan` are absolute, so the picture at p = 1 is identical before and after the commit (tested). Input is ignored while a pour runs (about 590 ms).
23. **Pour timeline:** 160 ms travel and tilt, `100 + 45 x amount` ms pour (max 280), 150 ms return. Longest case is 590 ms, under the 650 ms target.
24. **Tilt scales with fullness:** a fuller tube tilts 40 degrees, a nearly empty one up to 78 degrees, then tips 14% further as it drains. The source pours from the side of the destination it is on; if the tilted body would leave the board it passes over and pours from the other side (`chooseSide`).
25. **Liquid stays level in a tilted tube** by counter-rotating the liquid group about the surface. This is a visual approximation (surface height is not volume-conserving at extreme tilt).
26. **Undo is a quick level slide (240 ms)** between the two tubes involved, found by diffing the two states; it is not a reverse pour. Restart, add tube, and level change snap without animation.
27. **Reduce Motion:** follows the OS via `AccessibilityInfo` unless overridden. When on, pours become a 220 ms level change with no movement, tilt or stream; ambient waves, bubbles, sparks, shake, lift and the selection sweep are off.
28. **Particles:** one pooled array, at most 120 live, stepped on the UI thread. Sparks use a single pale-gold colour; per-colour sparks were not needed to look right.
29. **Colour-blind palette** is Okabe-Ito based (8 distinct values) and also turns patterns on. The base palette's violet was darkened (`#8447FF`) so violet and magenta differ by a luminance ratio above 1.5 (tested, as is blue/cyan).
30. **Settings** are a temporary toggle list on the level list screen, not persisted (Phase 3 adds the real screen and storage). The Hint button is hidden behind `features.hints`; `+ TUBE` is free in every level for now (coins arrive in Phase 3).
31. **Audio:** all sounds are silent 8 kHz WAV placeholders with their final names (`scripts/make-placeholder-sounds.ts`, `src/assets/sounds/README.md`). Up to 3 overlapping players per sound, pour pitch varied 0.94-1.06, music at 30% and ducked during the win sequence. Audio failures never reach gameplay.
32. **Win sequence** is about 2.2 s, skippable by tap: staggered tube glow, spark bursts, board brighten, win sound and haptics. The plain Phase 1 results panel now appears as an overlay at its end; the real overlay with coins is Phase 3.
33. **Web build for visual QA only.** Skia on web needs CanvasKit loaded first (`src/bootstrap.web.ts`) and `public/canvaskit.wasm` (`npm run web:setup`, not committed). `Skia.Path.MakeFromSVGString` fails on this web build, so `Icon` renders nothing there; native is unaffected. Colour labels need a system font and did not render in the web build, so they are unverified.

## Phase 3

34. **Navigation is Expo Router**, because the project's `AGENTS.md` requires it; it runs on React Navigation's native stack, which is what the spec asks for. Route files in `src/app/` are thin wrappers (`index`, `levels`, `settings`, `game/[levelId]`); the screens themselves stay in `src/screens/` as the spec's folder layout says. Screen options: no header, fade animation, swipe-back disabled on the game screen.
35. **Entry point** is `index.ts` -> `src/bootstrap.ts` (native: `expo-router/entry`). The web bootstrap loads CanvasKit first and then requires the router entry (used only for browser QA).
36. **Small icons, stars and the coin use `react-native-svg`**, not Skia. A Skia canvas needs its own GPU surface; a 25-card level grid with one canvas per card was heavy and exceeded the browser's WebGL context limit. Skia stays for the board, logo, splash and Home background.
37. **Packages added** (SDK 57 versions): `expo-router ~57.0.24`, `react-native-screens ~4.26.0`, `expo-linking`, `expo-constants`, `expo-splash-screen`, `@react-native-async-storage/async-storage 2.2.0`, `react-native-svg 15.15.4`; dev: `eslint 9`, `eslint-config-expo`. `expo lint` could not auto-configure (its API is blocked here), so `eslint.config.js` was added by hand and `npm run lint` runs ESLint. The `react-hooks/immutability` rule is off because it flags every Reanimated `sharedValue.value = x` write.
38. **Save layout.** `SaveDataV1` is split in memory: `progressStore` holds everything except settings, `settingsStore` holds the persisted settings (plus the OS reduce-motion flag, which is never saved). `services/persistence.ts` subscribes to both stores and schedules one debounced (500 ms) write of the combined save; it flushes when the app leaves the foreground.
39. **Load rules** (`parseSave`): run migrations, validate structure, fill missing optional sections with defaults, clamp coins at 0, and recompute `starsTotal`, `researchXp`, `highestUnlocked` and `levelsCompleted` from the level records. A save that is unreadable, structurally invalid, or from a newer version than the app is copied to `chroma.save.corrupt.<timestamp>`, defaults are used, and a one-time "SAVE RESET" toast is shown.
40. **In-progress level** is stored under `chroma.session` whenever the board changes (not on timer ticks) and when the app backgrounds, and is removed when the level is solved, or when the game screen is left by any route (including hardware back). CONTINUE therefore resumes after the app is killed or backgrounded, not after pressing Back. A resumed board with moves already made skips the tutorial.
41. **Completion is recorded the moment the puzzle is solved**, not when the overlay appears, so closing the app during the celebration still saves it. The overlay reads the result from `progressStore.lastCompletion`. Replaying a solved level records again (+5 coins, best moves and stars only improve).
42. **Rewards.** First completion +50; first time at 3 stars +25 (added on top, so a first 3-star clear is +75, plus any achievements); every later completion +5. Achievement coins are added when unlocked. Research XP is recomputed as 10 per best star plus 20 per daily completion. Lab level n needs `50 x (n-1)^2` XP (`economy.ts`). The home streak is hidden until the Daily Experiment exists.
43. **Extra tube price.** Free on levels 1-10, 100 coins from level 11. When the player cannot pay, the button is disabled and the price is shown greyed under the label. Coins are spent when the tube is added. Stars are capped at 2 as before.
44. **Tutorial** lives in `game/tutorial.ts` (pure, tested) and runs on level 1 for new players, or from Settings > Replay tutorial. Steps 1-2 accept only the highlighted tube; step 3 advances on a pour onto an occupied tube; step 4 ends after the next pour. Undo/Restart/+ Tube are disabled while it runs. SKIP appears only once the tutorial has been completed before. `tutorialDone` is set when level 1 is completed.
45. **Splash.** The native splash shows the first frame and is hidden as soon as the JS splash (logo plus a 1.2 s liquid fill) is laid out. The app shows Home only when both the fill and the save load have finished.
46. **Level select.** Chapter 1 (levels 1-10) and chapter 2 (11-25) are listed with cards; chapters 3-5 are dashed "Coming soon" rows. Locked cards show a lock and tapping one shows a "Complete level N first" toast. Daily, Laboratory and Collection buttons stay hidden behind `features.ts`.
47. **Not verified without a device:** AsyncStorage on native, the native splash, AppState flush on real backgrounding, and the double-confirmation Alerts for Reset progress (React Native's `Alert` does nothing on web).

## Phase 4

48. **Hint solver** is the same A* as the offline solver, refactored into a resumable `Search` class (`solver.ts`) that pauses when told to. `findHint` (`hints.ts`) runs it in slices of at most 8 ms with a frame (`requestAnimationFrame`) between slices, a 300 ms budget for the exact search, then up to 100 ms for a fast approximate search (weight 3). Results: a move (first move of the shortest line found), `solved`, `unsolvable` (exhaustive search proved the position lost), or `unknown` (out of time, or mechanics the solver cannot model yet). A search result is discarded if the board changed while it ran.
49. **Hint UI and pricing.** A ring appears on the source tube, then the destination 650 ms later; the toast names the visible colour ("Try moving CRIMSON here."); rings clear after 6 s or on the next tap, undo, restart or purchase. Hints are free on levels 1-10; from level 11 the first hint of a level visit is free and each later one costs 50 coins. Coins are charged only when a move hint is shown (not for "unstable" or "no hint available"). The unaffordable button is disabled with the price shown. Hints never change stars; `hintsUsed` feeds the `hints` stat. The daily puzzle (level number 0) always uses the paid rates.
50. **Daily puzzle.** Date key is the device's local date. Seed is `chroma-daily-<generator version>-<date>`. The spec (5 or 6 colours, medium or hard, optimal-move window) depends only on a hash of the date. Generation uses `LevelGenerator.tryNext()` (one deterministic attempt at a time) with a per-attempt solver budget of 60k nodes, at most 400 attempts, and it only accepts exactly solved puzzles, so the result does not depend on timing or slicing (tested: sliced equals one-shot). On the device it runs in 8 ms slices with a frame between them while the screen shows "SYNTHESISING". The result is cached under `chroma.daily` per date and generator version. If generation fails the puzzle comes from the 60 shipped, verified `daily.pool.ts` entries chosen by a date hash (`scripts/generate-daily-pool.ts`).
51. **Daily rules.** Only the first completion of a date pays (+100, plus 10 x streak day, max +70), moves the streak and counts for Plasma and XP (+20). Streak +1 if the previous completion was the day before, otherwise it restarts at 1; a completion dated before the last one (clock change) never breaks it. The displayed streak is 0 once a day has been missed. Replays may improve the stored best moves and time. The 7-day streak awards Weekly Research. There are no stars on the daily puzzle. A saved in-progress daily resumes through the cached level. `leaderboard.submitDaily` is called with a no-op implementation.
52. **Collection.** Nine items as in the spec. Coin items are bought, star items unlock at 25 and 40 stars, Plasma at 5 daily completions. Ownership of earned items is granted automatically when the requirement is met (also on load), and an equipped item that is not owned reverts to the default. Items can be previewed before unlocking; a preview is a live looping pour drawn with the real tube and stream components. Previews and purchases never touch gameplay.
53. **Cosmetics apply** to the game board (tube glass, backdrop and shelves, pour stream), the Home background (decorative tubes, bench, particles), the Laboratory scene and the previews. Sparkle adds glints and a spark burst where the stream lands; Plasma adds a glow and a jagged arc. Screen background colours of menu screens stay on the default palette.
54. **Laboratory.** The scene is one Skia canvas with seven vector drawings made for this game. Unlocked pieces animate in staggered (scale and fade) every visit and idle with a gentle pulse; locked pieces are dark silhouettes labelled with their star threshold, and the three pieces beyond the MVP are labelled "Future chapters". `labUnlocked` is recomputed from the star total on load, never trusted. Research XP is shown as lab level plus a progress bar. Reduce Motion shows everything static.
55. **`svgPath.ts`** builds Skia paths from a small SVG subset (M, L, H, V, C, Z) with a pure, tested parser, because Skia's own string parser is missing on the web build.
56. **Service stubs** from section 19 now exist (`analytics`, `ads`, `purchases`, `leaderboard`, `cloudSync`): an interface, a no-op implementation and a setter. Gameplay code calls only the interfaces.
57. **Not verified without a device:** hint timing on a mid-range phone (it is sliced, but I could only measure in Node and a software-GL browser), cosmetic rendering performance on devices, and real audio.

## Phase 5

58. **Levels.** Chapters 3-5 add 30 levels (26-35 Cryogenic Lab, 36-45 Unknown Compounds, 46-55 Quantum Chemistry), generated offline by `generateMechLevel` from the recipe table `MECH_SPECS` in `difficulty.ts` and written to `levels.mechanics.generated.ts` (separate from the classic file, which is byte-for-byte unchanged). Every level is solved exactly and verified by replaying the solution through the real engine. Difficulty is hard for 26-38 and expert after; the one-grade-drop rule holds across all 55. Colour mixing (11.6) is not implemented.
59. **Acceptance rule for generated mechanic levels.** A deal is kept only if it is exactly solvable within the per-level optimal-move window, is not a duplicate (the canonical key now includes frozen/hidden marks and per-tube rules), and the mechanic matters: either the optimum is longer than for the same deal without the mechanic, or (catalyst levels) the optimal line fires the catalyst. Frozen levels lengthen the optimum only by about a move, so their difficulty comes mostly from the constraints; mystery liquid adds about two moves on average.
60. **Reactor levels** are 30, 40 and 50 (one per ten levels). `moveLimit` is the optimum plus 4 and `bonusCoins` is 50. The meter fills per move; solving at exactly the limit still earns the bonus; past it the meter reads STABILISED and play continues. The bonus is paid once per level: a replay pays it only if no earlier run finished within the limit (derived from the stored best moves, so the save format is unchanged). Undo takes the meter back.
61. **Engine semantics.** Settle follows 5.5 and repeats until stable: reveal a hidden top, seal complete tubes (a locked tube cannot seal until it unlocks), catalyst (first pass only, on the tube just poured into, once), then unlock/thaw conditions, then solved. A hidden layer on top at the start is shown. A run stops at a frozen or hidden layer. `colorCompleted` and `tubesCompleted` count sealed tubes. A thaw or unlock that creates a completion cascades.
62. **Catalyst-driven targets keep a backup condition.** A locked or frozen tube that a catalyst helps still has its own condition, set to 40 moves, so the tube definition stays valid (`lock` and `thawWhen` are required by the data model) and the catalyst is a shortcut rather than the only way.
63. **Solver for mechanics.** `MechSearch` is the same A* but over real game states using the engine's own `pourLiquid`, so rules cannot drift. State key: tubes that carry rules (lock, thaw condition, catalyst) or are named by a catalyst keep their positions, the rest are sorted; the move count (capped at the largest `movesMade` threshold) is part of the key only while such a condition exists. The heuristic (colour runs minus goal runs, true colours) stays admissible. Classic levels keep the faster string solver; a test checks both give the same optimum on classic levels. `solveState` and `findHint` take the level for positions with mechanics; without it they say unknown. Hints on mechanics levels may time out more often (the engine-based search is slower than the string search).
64. **Rendering.** Frozen layers show frost, cracks and a cool rim glow, and thaw with a melt and a warm glow. Mystery layers are dark with a pulsing "?" and dissolve to their true colour. Locked tubes are dimmed with a padlock and a counter such as "3/5 moves" (also read by screen readers); the padlock swells and fades on unlock. A catalyst tube has a pulsing core tinted by its trigger colour; activation draws a ring burst and an arc to the target, and the target's own animation starts about 380 ms later. Reduce Motion skips the arcs and plays the changes instantly. Each level shows its rules in plain language under the top bar, and the reactor shows a meter.
65. **Laboratory thresholds.** With 55 levels the maximum is 165 stars, so the Quantum Analyzer (100) and Advanced Reactor (140) are now reachable; only the Holographic Display (180) is labelled "Future chapters".
66. **Not verified without a device:** performance of the extra frost, veil and lock drawing on a mid-range phone, and the new sounds (placeholders are silent).

## Colour mixing (Chapter 6)

67. **Rules as approved.** red + blue = purple, blue + yellow = green, red + yellow = orange; cyan, pink and mixed colours are inert. A mixing pour moves exactly one unit; that unit and the destination's top unit become two units of the result, so volume is conserved and the destination needs one free space. Pairs are opt-in per level (`rules.mixing.pairs`, copied into `GameState.mix`). A frozen top on either side blocks a mix.
68. **Engine.** `src/game/mixing.ts` holds the table and `isMixPour`; the mix branch lives in `getMoveError`, `getPourAmount` and `pourLiquid`. A mix emits `poured` (amount 1) then `mixed`. A catalyst fires if the poured or the produced colour is its trigger. Saves restore `mix` from the level, and the consistency check compares total units for mixing levels (colours change, volume does not).
69. **Solver.** Mixing levels use `MechSearch`. A mixing pour can remove two colour runs, so the bound is `max(ceil(d/2), d - floor(inputUnits/2))` where `d` is runs minus goal runs and the goal is total units / capacity. Tests compare weight 0 with weight 1 on random boards. The canonical level key keeps colours distinct for mixing levels.
70. **Chapter 6 "Chromatic Synthesis", levels 56-65.** Every level has a colour whose unit count is not a multiple of four, which proves (without search) that it cannot be solved with mixing off; the generator also requires at least one mix in the optimal line. 60 is the reactor level; 62 and 64 add hidden layers; 65 adds a locked tube. Difficulty is hard (56-61) then expert, so it never drops two grades after level 55. Level 63 is shorter than 62 (13 against 17 moves) because its recipe supports no longer deals; kept for variety.
71. **The daily puzzle never mixes** (tested). The Holographic Display (180 stars) is now reachable with 195 stars, so no lab item says "Future chapters" any more (supersedes 65).
72. **Interface.** Recipe legend under the top bar; selecting a tube shows the result colour above every tube it would mix with (also in the screen reader label); a mixed pour plays the `mix` sound and sparks; hints say "Try mixing X into Y". The pour animation is the normal one with a single drop (superseded for the colour change by 85). Undo slides the mixed unit back.
73. **Mixing tutorial** (`tutorial: 'mixing'`, level 56, first play or forced): three steps, never restricts taps, always skippable.
74. **Not verified without a device:** the feel of the mix animation, and the (silent) `mix.wav`, on hardware.

## Phase 7 (code review and mix animation polish)

83. **Review findings fixed.** (a) `createSearch` treated a mixing state without its level as a classic board and would have reported it unsolvable; it now returns null like other mechanic states (test added). (b) Dead parameters in `pour.ts` and `mechGenerator.ts`. Nothing else found in the engine: a new property test plays 80 random moves on every shipped level (65 levels, half with the purchased extra tube) and checks conserved volume (and colours on non-mixing levels), no overflow, no hidden layer on top, sealed tubes stay full, move counter equals history, save/load round-trips, and undo returns exactly the starting board.
84. **Reviewed and left alone:** date handling for the daily streak (UTC day arithmetic, local date keys), persistence flush on background, touch targets (all at least 44 dp on controls), `eslint-disable` in `GameBoard` (the effect must run only when the engine state changes). The Home streak does not refresh if the app stays open across midnight; it refreshes on the next render, which is acceptable.
85. **Mix crossfade.** A mixing pour now blends the arriving drop and the unit it lands on toward the result colour in step with the pour, and the pattern/label switches at the halfway point. Undo runs it backwards (the leaving unit stays the result colour while the pair turns back). Implemented as optional `Plan` fields and a pure worklet `slotLookAt` (unit-tested); plain pours are unchanged.
86. **Not verified:** the blend could not be captured frame by frame (the software-GL browser finishes the pour between screenshots); only the end state and the logic tests were checked. Please watch a mix on a device.

## Phase 8 (chapter 7)

87. **Chapter 7 "Full Spectrum", levels 66-75.** Mixing combined with the other mechanics: frozen layers (66, 67, 70, 71, 75), mystery layers (72-75), locked tubes (68, 69, 74, 75) and catalysts (68, 69, 71, 72). All are `expert`, unsolvable without mixing, proven by exact search, and the level generator keeps only deals whose optimal line mixes at least once. 70 is the reactor level. Levels 1-65 regenerate byte-for-byte unchanged.
88. **Catalysts and mixing.** A mixing catalyst's trigger colour may be one that only exists after a mix (the engine already fires on the produced colour). A catalyst level is kept only if the optimal line fires it; its target also has a 40-move backup condition so the catalyst is a shortcut rather than the only route. A recipe with two frozen tubes and a thaw catalyst was dropped: the 40-move backup made the search too large to prove optimal in reasonable time.
89. **Totals.** 75 levels and 225 stars. Rules text on the busiest level (75) is five lines plus the recipe legend; the board still fits at 360x640, but a future pass could collapse the rules into a "?" panel.

## Phase 9 (rules panel)

90. **Rules behind a button.** The level's special rules (previously up to five lines of text pushing the board down) now sit behind a `RULES (n)` button under the recipe legend. Opening it shows a card over the board, so the board keeps its height; the button or `GOT IT` closes it. `MechanicsNote` was replaced by `RulesPanel`.
91. **Auto-open briefing.** The card opens by itself on the first play of a level with special rules (never completed, no moves yet), except on levels where a tutorial already explains the rules (1 and 56) and on resumed boards. `shouldAutoOpenRules` in `mechanicsText.ts` holds the rule (tested). The reactor line stays with the meter. The recipe legend stays visible; on three-recipe levels it wraps to two lines.

## Phase 10 (performance work)

92. **Adaptive quality** (`src/render/quality.ts`). The board feeds its own frame times to a small governor. After a 2 s warm-up, 2 s of smoothed frame time above 24 ms (about 41 fps) switches to a `LITE` tier; 15 s below 18 ms (about 55 fps) switches back, and after two step-downs it stays light (no flapping). Stalls over 120 ms (backgrounding) are ignored. `LITE` runs the idle shimmer at 20 Hz instead of every frame, stops ambient bubbles and halves particle bursts. Pours, the stream and every rule always run at full rate; nothing about gameplay changes.
93. **Less work per frame.** (a) Tubes that are neither source nor destination of the running pour no longer recompute their liquid on every frame (an `involvedProgress` value gates it). (b) The particle layer fills its paths without allocating arrays and objects each frame (`addCirclesOfKind`; Node microbenchmark: about 4.7 us to 1.5 us per frame for 100 live particles, so the gain is mostly less garbage collection). The first is expected to matter most on 8-9 tube boards during a pour.
94. **Frame-rate overlay behind a flag.** `features.perfOverlay` (env `EXPO_PUBLIC_PERF_OVERLAY=1`, set in the `preview` EAS profile) shows fps, worst frame and the tier on the board. It costs nothing when off (the counters are not touched).
95. **Not measured on devices.** The software-GL browser ran at about 25-40 fps and the governor correctly stepped down to `LITE` there, which exercised the logic end to end, but I have no before/after numbers from a phone. Treat 92-93 as plausible improvements until the device plan reports real numbers; tune the thresholds in `quality.ts` from them.
